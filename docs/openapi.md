# OpenAPI Schemas

The server publishes its OpenAPI document at `/openapi/v1.json` (development only), generated by
`Microsoft.AspNetCore.OpenApi` and rendered by [Scalar](https://scalar.com) at `/scalar/v1`. The document is enriched by
the schema transformers registered in `addOpenApiToBuilder` (`Program.fs`).

F# types need help here: the underlying `System.Text.Json` schema exporter does not understand F# unions, so without a
transformer a discriminated union becomes an empty schema (`{}`).

## Native attributes (prefer these)

ASP.NET Core already maps `System.ComponentModel.DataAnnotations` attributes onto JSON Schema keywords, so prefer them
whenever they express the constraint. They need no custom code.

| Attribute                                                     | Schema keyword                                                   |
| ------------------------------------------------------------- | ---------------------------------------------------------------- |
| `[<MinLength(n)>]`, `[<MaxLength(n)>]`, `[<StringLength(n)>]` | `minLength` / `maxLength`                                        |
| `[<Length(min, max)>]`                                        | `minLength` / `maxLength` (or `minItems` / `maxItems` on arrays) |
| `[<Range(min, max)>]`                                         | `minimum` / `maximum`                                            |
| `[<RegularExpression(pattern)>]`                              | `pattern`                                                        |
| `[<Url>]`                                                     | `format: uri`                                                    |
| `[<Base64String>]`                                            | `format: byte`                                                   |
| `[<Description>]`                                             | `description`                                                    |
| `[<Obsolete>]`                                                | `deprecated`                                                     |
| `[<DefaultValue>]`                                            | `default`                                                        |

Do **not** put `[<Required>]` on an F# record. Record fields are exposed without a setter, so schema generation throws
(`JsonPropertyInfo ... is marked required but does not specify a setter`) and the document request fails with a 500.
Required fields are inferred from non-`option` fields by `FSharpRecordSchemaTransformer`.

Reference a `[<Literal>]` for bounds so they are not duplicated, e.g. `[<MaxLength(ItemName.MaxLength)>]` rather than a
bare `128`.

```fsharp
type CreateBalanceSheetItemRequest = {
    [<MinLength(1)>]
    [<MaxLength(ItemName.MaxLength)>]
    Name : string
    // ...
}
```

## `SchemaHint` attributes (only for the gaps)

Reach for the attributes in `Budgeteur.Shared.OpenApi.SchemaHint` only when the native attributes cannot express the
constraint. (The `Attribute` suffix is optional: `SchemaHint.Enum` and `SchemaHint.EnumAttribute`, and likewise
`Number`, are the same type.)

- `SchemaHint.Enum(typeof<ItemKind>)` documents a property as a `string` enum whose values are the union's case names.
  The native mapping only understands C# enums, not F# unions. The reflected values must match the wire strings; they do
  for the domain enums, whose `toString` returns the case names. If a case name ever diverges from its wire value,
  reflect a dedicated union whose names match, or fall back to `[<RegularExpression>]`.
- `SchemaHint.Number(Minimum = "0", MultipleOf = 0.01)` constrains a numeric property. Use it for a minimum-only or
  maximum-only bound, or for `multipleOf`, which `[<Range>]` cannot express because it requires both bounds. Leave a
  bound blank to omit it.

```fsharp
type CreateBalanceSheetItemRequest = {
    [<SchemaHint.Number(Minimum = "0", MultipleOf = 0.01)>]
    Balance : decimal

    [<SchemaHint.Enum(typeof<ItemKind>)>]
    Kind : string
    // ...
}
```

Hints describe the published document only; they do not validate requests. Domain invariants in `Domain/` remain the
source of truth, so keep the hints in step when a rule changes.

## Wiring

`addOpenApiToBuilder` (`Program.fs`) registers these transformers, in order:

- `FSharpOptionSchemaTransformer` (from `Oxpecker.OpenApi`) - renders `option`/`voption` as nullable.
- `FSharpRecordSchemaTransformer` - marks non-`option` record fields required and fixes string type inference.
- `XmlDocSchemaTransformer` - populates descriptions from F# XML doc comments.
- `SchemaHintTransformer` - applies the `SchemaHint` attributes.
- `DecimalSchemaTransformer` - documents `decimal` as a plain `number`. Without it, `System.Text.Json` infers a
  `number`-or-`string` union with `format: double` and a numeric-string pattern.

### Decimal wire format

The document says `decimal` is a `number`, but the server encodes decimals as JSON strings (Thoth's `Encode.decimal`)
and the client sends strings too. Requests currently accept either, so the mismatch is only on the response side.
Revisit this if the encoder or the client ever changes.

## Future migrations and alternatives

- **Oxpecker.OpenApi PR #98** (unreleased) adds `FSharpUnionSchemaTransformer`, which documents F# unions generically
  and can replace the `SchemaHint.Enum` half once released. It targets .NET 11 and does not unwrap single-case wrapper
  types.
- **FSharp.Data.JsonSchema.OpenApi** (`AddSchemaTransformer<FSharpSchemaTransformer>()`) documents multi-case unions as
  `anyOf` and fieldless unions as enums, but does not unwrap single-case refined types and does not carry
  `DataAnnotations`.
- **Giraffe.OpenApi** ships a `DiscriminatedUnionSchemaTransformer` that maps fieldless unions to a camelCase string
  enum.
- **.NET 11** adds built-in `System.Text.Json` _serialization_ for F# unions (dotnet/runtime #125610), but no
  OpenAPI/JSON Schema support for them.
- **Refined single-case unions**: if a type like `type ItemName = ItemName of string` is ever used directly as a field
  type, add a transformer that unwraps it to its underlying primitive plus constraints. `FSharp.Data.JsonSchema` has an
  unimplemented `UnwrapSingleCaseDU` option for this.
- **`JsonSchemaExporterOptions.TransformSchemaNode`** is the lower-level `System.Text.Json` hook, but ASP.NET Core
  consumes it internally, so `IOpenApiSchemaTransformer` is the public extension point.
