# OpenAPI Schemas

In development the server publishes its OpenAPI document at `/openapi/v1.json`, generated by
`Microsoft.AspNetCore.OpenApi`, and renders it with [Scalar](https://scalar.com) at `/scalar/v1`. The document is not
served in production.

The underlying `System.Text.Json` schema exporter does not understand F# types: without help, a discriminated union
becomes an empty schema and option or record fields get the wrong nullability. Custom schema transformers fill the gaps;
each documents its purpose in `Shared/OpenApi.fs`. This doc covers the conventions endpoint authors follow.

## Native attributes first

ASP.NET Core maps `System.ComponentModel.DataAnnotations` attributes onto JSON Schema keywords, so prefer them whenever
they express the constraint. They need no custom code.

| Attribute                                                     | Schema keyword                                                   |
| ------------------------------------------------------------- | ---------------------------------------------------------------- |
| `[<MinLength(n)>]`, `[<MaxLength(n)>]`, `[<StringLength(n)>]` | `minLength` / `maxLength`                                        |
| `[<Length(min, max)>]`                                        | `minLength` / `maxLength` (or `minItems` / `maxItems` on arrays) |
| `[<Range(min, max)>]`                                         | `minimum` / `maximum`                                            |
| `[<RegularExpression(pattern)>]`                              | `pattern`                                                        |
| `[<Url>]`                                                     | `format: uri`                                                    |
| `[<Base64String>]`                                            | `format: byte`                                                   |
| `[<Description>]`                                             | `description`                                                    |
| `[<Obsolete>]`                                                | `deprecated`                                                     |
| `[<DefaultValue>]`                                            | `default`                                                        |

- **No `[<Required>]` on F# records.** Record fields have no setter, so schema generation throws and the document
  request fails with a `500`. Non-`option` fields are marked required automatically.
- **Bounds reference the domain.** Use the domain's `[<Literal>]` constants for bounds rather than repeating numbers, so
  the document follows the invariant.
- **Descriptions come from XML doc comments** on DTO fields.

## Schema hints for the gaps

When no native attribute fits, use the `SchemaHint` attributes in `Shared/OpenApi.fs`:

- **Enums from F# unions.** A string field holding a union case name is documented as an enum of the union's case names.
  This relies on case names matching the serialised strings; if one ever diverges, document a dedicated union whose
  names match, or fall back to a pattern.
- **Non-negative money.** Marks a decimal field whose domain forbids negative values (balances, totals). Signed values
  (transaction amounts, net worth, working capital) need no attribute.

Hints describe the document only; they do not validate requests. Domain invariants remain the source of truth, so keep
hints in step when a rule changes.

## Decimals

Decimals are encoded as JSON strings, and the client sends strings, so every `decimal` is documented as a `string` with
a money pattern allowing at most two fraction digits (unsigned for non-negative money). A string schema cannot carry
`minimum`, `maximum`, or `multipleOf`, so those keywords are not published.

The request decoder also accepts a JSON number. The document keeps the canonical string form, since that is what both
sides send. Revisit if the encoder or the client changes.

## Alternatives considered

Replace the custom transformers when one of these covers the same ground:

- **Oxpecker.OpenApi PR #98** (unreleased) adds a union transformer that could replace the enum hint. It targets .NET 11
  and does not unwrap single-case wrapper types.
- **FSharp.Data.JsonSchema.OpenApi** documents multi-case unions as `anyOf` and fieldless unions as enums, but does not
  unwrap single-case refined types and does not carry `DataAnnotations`.
- **Giraffe.OpenApi** maps fieldless unions to a camelCase string enum.
- **.NET 11** adds `System.Text.Json` serialisation for F# unions (dotnet/runtime #125610), but no schema support.
- **Refined types as DTO fields.** DTOs hold primitives only. If a refined type is ever used directly as a field type,
  add a transformer that unwraps it to its primitive plus constraints.
- **`JsonSchemaExporterOptions.TransformSchemaNode`** is the lower-level hook, but ASP.NET Core consumes it internally,
  so schema transformers are the public extension point.
